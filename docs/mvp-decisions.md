# 카공맵 MVP 결정사항

- 작성일: 2026-08-12
- 프로젝트 성격: **개인 습작 (인프런 VC 클래스)**
- 근거 리서치: [research-verification.md](./research-verification.md)

## 0. 전제

사업 타당성 검증이 아니라 **습작 MVP**다. 이 전제가 아래 모든 결정의 기준이다.
"돈이 되는가"에 답할 필요가 없으므로, 리서치에서 나온 사업 리스크 대부분은 의사결정에서 제외한다.
대신 **습작이어도 실제로 물리는 제약**(API 약관, 과금, 데이터 신선도)만 남겨 설계에 반영한다.

## 1. 스코프에서 제외한 것

| 항목 | 제외 사유 |
|---|---|
| 수익모델 (광고/구독/제휴) | 습작에 불필요 |
| 업주 온보딩·제휴 | 공급자 측 이해충돌은 사업 단계 문제 |
| 스터디카페와의 경쟁 구도 | 시장 판단이지 구현 판단이 아님 |
| 시장 규모 추정 | 동일 |
| 카공지도(선행 서비스) 부검 | 진행 여부를 결정할 필요가 없어짐. 기능 참고용으로만 활용 |

**단, 발표·포트폴리오 서사에는 활용한다.**
"왜 이 문제인가"를 설명할 때 리서치의 [사실] 항목 2~3개만 인용:
- 카페의 콘센트 유료화(30분 990원 / 1시간 1,980원), 노트북 사용 금지 사례 존재
- 커피음료점 95,337개 (2025년 1분기, 국세청 TASIS) — 선택지는 많은데 고를 기준이 없다
- 네이버 플레이스 키워드 리뷰에 "노트북하기 좋아요"가 존재하나, 지도 위 결합 필터는 없음

## 2. 스코프에 남긴 제약 (습작이어도 실제로 물림)

### 2-1. 데이터 수집: 크롤링 금지, 수동 큐레이션으로 간다 — **확정**

**결정: 카페 데이터는 직접 수집·수기 입력한다. 크롤링하지 않는다.**

근거:
- 카카오맵 API FAQ에 **"로컬 API 응답 결과 데이터는 별도 저장하여 사용할 수 없음"** 명시
- 카카오 데브톡에 "정책 및 약관 위반에 따른 API 차단 예정 조치" 공지·사례가 반복 게시됨
  → 집행이 실제로 이루어짐. 습작이라고 예외 없음
- 포트폴리오로 공개할 프로젝트에서 데이터 출처가 크롤링이면 그 자체가 약점

**습작에서는 오히려 유리한 선택이다.** 수집 규모가 작아도 되고, 데이터 품질을 직접 통제할 수 있다.
현재 `data/cafes.json`이 이미 이 방식이다.

### 2-2. 지도 SDK: 카카오맵 JavaScript SDK — **확정**

| 후보 | 판단 |
|---|---|
| **카카오맵 JS SDK** | **채택.** 2026-07-21부터 개발자 계정 기준 "첫 번째로 활성화한 앱"에 무료 쿼터 제공. 습작 앱 1개면 무료 범위 내 |
| 네이버 지도 API | 제외. 신규 신청 차단 2025-05-22 / 무료 혜택 종료 2025-07-01 → 유료 과금 전환 |
| Google Maps Platform | 제외. 국내 POI·길찾기 정확도 낮음 |
| Leaflet + OSM | 제외. 비용 0이지만 국내 POI 표기가 빈약해 "카페 지도" 화면이 초라해짐 |

주의: 무료 쿼터는 **계정의 첫 활성화 앱 1개 한정**이다. 앱을 여러 개 만들지 말 것.

### 2-3. 데이터 신선도: 숨기지 말고 UI로 드러낸다 — **확정**

콘센트·영업시간·정책은 금방 낡는다. 습작 규모에서 최신성을 보장할 방법은 없다.
→ **회피하지 말고 인정한다.** 각 카페에 `last_verified` 필드를 추가하고 화면에 노출한다.

"2026-08-12 확인" 같은 표기는 습작에서 오히려 성숙도를 보여주는 포인트다.
문제를 숨기지 않고 UI로 다룬 것이므로.

## 3. MVP 범위

### 포함
- **대상 지역 1곳 고정**: 송리단길 · 석촌호수 일대 (현재 시드 데이터 위치)
- **지도 + 핀 + 카드 리스트** 2단 레이아웃
- **결합 필터** — 이 프로젝트의 유일한 차별 화면. 여기에 가장 힘을 쏟는다
  - 콘센트 (`many` / `some`)
  - 조용함 (`noise`)
  - 지금 영업중 (`open_time` / `close_time` / `is_24h` 기준 실시간 판정)
  - 가격대 (`iced_americano_price`)
- **상세 정보**: 사진 + 스펙 + 네이버 플레이스 링크
  - **사진을 직접 호스팅한다** — Supabase Storage `place-images` 버킷. 마커에 대표 사진 한 장,
    상세 패널에 전체를 좌우 슬라이드로 보여준다. URL은 `places.photos`에 담는다.
  - ⚠️ **2026-08-14에 뒤집은 결정이다.** 원래는 "사진은 넣지 않는다 (저작권). 상세는 네이버
    플레이스로 넘긴다"였다. 뒤집은 이유는 습작에서 사진 없는 카페 카드가 실제로 쓸모를 잃기
    때문이고, 저작권 문제가 해소돼서가 아니다.
  - ⚠️ **지금 올라간 9장은 연습용 임시 이미지이며 이용 권리를 확인하지 않았다.** 습작을 넘어
    공개하려면 직접 촬영본이나 사용 허가를 받은 사진으로 **교체해야 한다.** 이 제약이 풀리기
    전까지 이 기능은 로컬 습작 범위에 묶어둔다.
  - 카카오맵 API 응답에서 얻은 이미지 URL은 넣지 않는다 — 응답 데이터의 별도 저장은 약관
    위반이다 (위 크롤링 금지와 같은 근거).
- **링크 미리보기** — 카카오톡·슬랙·디스코드에서 링크를 펼쳤을 때 뜨는 카드. 2026-08-21에
  들어왔다. 첫 사용자에게 주소를 보내는 것이 이 습작의 유일한 배포 경로라, 카드가 안 뜨면
  링크가 그냥 문자열로 보인다.
  - OG 이미지는 `app/opengraph-image.tsx`가 만든다. **카페 사진을 쓰지 않는다** — 아래
    이용 권리 문제가 공유 링크로 같이 퍼진다. 워드마크와 문구만 넣었다.
  - ⚠️ **검색 색인은 막아 두었다** (`app/layout.tsx`의 `robots: { index: false }`).
    같은 이유다 — 권리를 확인하지 않은 사진 9장이 검색 결과에 남는 것을 원하지 않는다.
    **사진을 교체하면 그 줄을 지운다.**
  - 색인 차단을 `robots.txt`가 아니라 meta로 하는 이유는 슬랙의 링크 펼치기 봇이
    `robots.txt`를 지키기 때문이다. `Disallow: /`를 두면 카드까지 같이 사라진다.

### 제외
| 항목 | 사유 |
|---|---|
| UGC / 리뷰 | 콜드스타트 문제를 아예 만들지 않는다 |
| 실시간 혼잡도 | 데이터 소스 부재. 습작 범위에서 구현 불가 |
| 전국 확장 | 1개 생활권으로 고정 |
| 공유 | MVP 이후 |

- ⚠️ **로그인은 2026-08-15에 이 표에서 빠졌다.** 원래 근거였던 "콜드스타트를 만들지
  않는다"는 **UGC에만 해당한다** — 로그인 자체는 사용자에게 채워달라고 요구하는 게
  없다. 카카오 로그인을 1차에 넣은 이유는 인증 경로를 먼저 뚫어두기 위해서다.
  세션을 어디에 두느냐(쿠키 vs localStorage)가 데이터 계층 전체를 가르는데,
  이걸 북마크를 만드는 시점에 정하면 그때 다 뒤집게 된다.
- ⚠️ **즐겨찾기(북마크)도 2026-08-15에 이 표에서 빠졌다.** 같은 날 오전에 "로그인이
  생겼다고 딸려오지 않는다"고 적은 것을 오후에 뒤집었다. 근거는 로그인만 있고 쓸 일이
  없으면 **인증 경로가 맞는지 검증할 수단이 없다**는 것이다. 세션·RLS·낙관적 갱신을
  실제로 굴려보는 기능이 하나는 있어야 한다.
  - 북마크는 **콜드스타트를 만들지 않는다.** 남에게 보이지 않는 개인 데이터라 아무도
    쓰지 않아도 다른 사용자의 화면이 비어 보이지 않는다. 위 UGC 제외 근거가 여기에는
    해당하지 않는다.
- **리뷰와 제보는 그대로 제외다.** 그쪽은 콜드스타트가 그대로 걸린다. 로그인이
  생겼으니 뭐라도 붙이자는 순서로 가면 이 표가 조용히 무너진다.

## 4. 기술 스택

- **프레임워크**: Next.js (App Router, 16.x)
- **지도**: 카카오맵 JavaScript SDK
- **데이터**: Supabase `places` 테이블. `data/cafes.json`은 시드 마이그레이션을 만드는
  입력으로만 남았다 (2026-08-14 변경)
- **배포**: Vercel — https://cagongmap-nu.vercel.app (2026-08-21 확정)

주소는 `NEXT_PUBLIC_SITE_URL`로 받고 `lib/site.ts`가 한 곳에서 읽는다. canonical과
og:image 절대 URL이 전부 이 값에서 나오므로, 도메인을 옮길 때 고칠 곳은 `.env` 하나다.

## 5. 데이터 스키마

현재 `data/cafes.json` 스키마를 유지하고 `last_verified`만 추가한다.

```jsonc
{
  "name": "나루터",
  "address": "서울 송파구 백제고분로41길 19-1 2층",
  "lat": 37.5077632,
  "lng": 127.1072485,
  "naver_place_url": "https://map.naver.com/p/entry/place/1747832649",
  "open_time": "12:00",
  "close_time": "00:00",
  "is_24h": false,
  "iced_americano_price": 4800,
  "outlet": "many",        // many | some | few
  "wifi": true,
  "noise": "quiet",        // quiet | normal | noisy
  "work_fit": "good",      // good | ok | bad
  "tags": ["넓은매장", "대형테이블", "콘센트많음"],
  "last_verified": "2026-08-12"   // 추가 예정
}
```

**확인 필요**: 기존 시드의 `work_fit` / `noise` 값이 직접 방문으로 판정된 것인지,
리뷰를 보고 추정한 것인지. 후자라면 판정 기준을 문서화해 두는 편이 좋다
(습작이라도 "이 값이 어디서 왔는가"는 발표 때 나올 질문).

## 부록: 이 결정이 뒤집히는 조건

습작 → 실제 서비스로 전환할 경우 아래를 다시 검토해야 한다.

- 카카오맵 무료 쿼터 초과 → 비즈월렛 연결 및 사용량 기반 과금
- 수동 큐레이션의 갱신 공수 한계 → UGC 도입 필요, 이때 콜드스타트 문제가 되살아남
- 네이버/카카오가 키워드 기반 지도 필터를 정식 제공하면 차별점 소멸
  → **미확인 항목이므로 네이버 지도 앱에서 직접 확인해 볼 것**
