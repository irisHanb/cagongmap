# Content Quality / E-E-A-T 평가 — cagongmap-nu.vercel.app

평가 대상: `/` 단일 라우트, Next.js 16 client-rendered SPA (fullscreen 지도 + 상세 패널).
`noindex, nofollow`가 걸려 있는 현재 상태를 전제로 하되, orchestrator 지시대로 **noindex가 풀렸을 때를 기준으로** 평가한다.

## 요약 점수

| 항목 | 점수 | 비고 |
|---|---|---|
| Content quality (종합) | **28 / 100** | 콘텐츠라기보다 UI. 텍스트 표면이 사실상 없다 |
| AI citation readiness | **15 / 100** | JSON-LD 0개, per-cafe URL 없음, 구조화 사실이 클릭 뒤에 숨음 |
| E-E-A-T 종합 | **32 / 100** | Trustworthiness의 `last_verified` 하나가 사실상 유일한 강점 |

## 1. 렌더링 구조와 텍스트 표면 (가장 중요한 발견)

- **Raw HTML(서버가 준 초기 응답)의 body 텍스트는 46자다**: `WORK CAFE MAP 카공맵 오래 앉아 작업하기 좋은 카페 9곳 카페 제보하기`.
  이게 전부다. 비JS 크롤러(대부분의 검색엔진 1차 fetch, 그리고 GPTBot·PerplexityBot처럼
  JS를 실행하지 않는 AI 크롤러)가 보는 것은 이 46자뿐이다.
- 카페 9곳의 데이터(주소·좌표·콘센트·소음·와이파이·가격·영업시간·태그·last_verified)는
  실제로 HTML 안에 **들어 있다** — 단, `self.__next_f.push(...)`로 감싼 RSC flight
  payload의 escaped JSON 문자열로만 존재한다. `<body>`에 렌더된 마크업이 아니다.
  → **JS를 실행하는 크롤러(Googlebot 2차 렌더, ChatGPT의 브라우징 도구 등)는 데이터에
  닿을 수 있지만, "본문 텍스트"로 파싱되는 게 아니라 JSON blob으로 존재하므로 검색엔진의
  본문 추출기(예: trafilatura류)는 대부분 걸러낸다.**
- Playwright로 완전히 렌더링해도(마커를 클릭하지 않은 최초 진입 상태) 화면에 실제로
  그려지는 텍스트는 여전히 `250m / WORK CAFE MAP / 카공맵 / 오래 앉아 작업하기 좋은 카페 9곳 / 카카오 로그인 / 카페 제보하기` 수준이다.
  **카페 개별 정보(Quick Check, 태그, 리뷰, 확인일)는 마커를 클릭해야만 DOM에 나타난다.**
  이건 스크롤이나 지연 로딩이 아니라 **사용자 상호작용(클릭) 이후에만 존재하는 콘텐츠**라
  대부분의 렌더링 크롤러가 실행하는 "페이지 로드 + 대기" 패턴으로는 수집되지 않는다.
- **카페별 고유 URL이 없다.** `/?cafe=naruteo` 같은 deep link나 `/cafe/naruteo` 같은
  개별 페이지가 없어서, 검색엔진이나 AI가 "나루터"라는 개별 엔티티를 가리킬 URL 자체가
  없다. 9곳 전부가 `/` 하나로 뭉쳐 있다.

**결론**: 지금 구조에서는 noindex를 풀어도 색인될 텍스트가 사실상 없다. 이건 "얕은
콘텐츠(thin content)"가 아니라 **콘텐츠가 크롤러 관점에서 존재하지 않는** 상태다.

## 2. 클릭 이후 콘텐츠의 질 — word count / 구조

마커를 클릭해 상세 패널(`CafeCard.tsx`)을 열면 나오는 구성:

```
사진 캐러셀 → 주소 → 이름 → 네이버 지도 링크 → QUICK CHECK(콘센트/소음/와이파이/
아메리카노 가격/영업시간, 5개 fact) → 태그 chip(평균 6.1개) → REVIEW(좋아요/그냥그럼/별로
집계) → last_verified 날짜 → "정보가 다른가요?" 버튼
```

- 카페 1곳당 텍스트를 다 합쳐도 **25~30 단어 안팎**이고, 전부 label:value 구조의
  단편(fragment)이다. **완결된 문장이 단 한 개도 없다.** "이 카페는 왜 좋은지", "언제
  가면 좋은지", "어떤 자리가 좋은지" 같은 서술형 정보가 전혀 없다.
- 9곳을 다 합쳐도 총 텍스트량은 **250단어 남짓**으로 추정된다. 스킬 기준표의 어느
  page type 최소값(홈페이지 500, 서비스 페이지 800...)에도 못 미친다.
  - 다만 이건 "기사형 페이지"가 아니라 지도 도구(utility)라는 점은 감안해야 한다.
    Google도 word count 자체를 랭킹 요인으로 보지 않는다. 문제는 분량이 아니라
    **어떤 형태로도 서술적 근거(왜 이 카페가 work_fit=good인지)가 존재하지 않는다는 것**이다.
- `tags`(예: "콘센트많음", "심야영업", "송리단길")는 검색엔진 입장에서 키워드 신호는
  주지만, 자연스러운 문장이 아니라 SEO 관점에서는 오히려 keyword stuffing에 가까운
  형태로 읽힐 수 있다. 태그 나열 자체가 문제는 아니나, 이를 뒷받침하는 서술 문장이
  전혀 없다는 게 문제다.

## 3. E-E-A-T 세부 평가

### Experience (경험 신호) — 20% 가중치, 추정 20/100

- **잠재력은 있으나 전혀 드러나지 않는다.** `outlet: many/some/none`, `noise: quiet/...`,
  `iced_americano_price` 같은 필드는 실제로 현장에 가서 확인해야 채울 수 있는 값이다
  (CLAUDE.md도 "카페 데이터는 수기 큐레이션으로만 채운다"고 명시). 이건 QRG가 말하는
  "직접 해본 사람"의 신호가 될 수 있는 원재료다.
- 하지만 이 사실이 **화면 어디에도 문장으로 서술되지 않는다.** "직접 방문해 콘센트
  개수를 셌습니다" 같은 진술이 없으면, 크롤러도 사용자도 이 숫자가 어디서 왔는지 알 길이
  없다. 데이터의 출처(1인 운영자의 현장 확인)를 밝히는 about/소개 페이지가 없다는 게
  가장 큰 손실이다.
- 사진 9장은 CLAUDE.md에 "연습용 임시본이며 이용 권리 미확인"이라고 명시돼 있다.
  본인이 직접 찍은 사진이라는 확인이 안 되면, 사진도 경험 신호로 쓸 수 없다.
- 리뷰(좋아요/그냥그럼/별로) 집계는 사용자생성콘텐츠(UGC)이긴 하나, 텍스트 리뷰가
  아니라 3지선다 카운트라서 "경험을 서술한" 콘텐츠로 보기 어렵다.

### Expertise (전문성) — 25% 가중치, 추정 15/100

- 운영자가 누구인지, 어떤 기준으로 `work_fit`을 매기는지(good/ok 등급 기준, 소음
  판정 방법, 콘센트 many/some/none의 경계) 설명하는 지면이 전혀 없다.
- 저자 정보(이름/자격/소개)가 사이트 어디에도 없다. `AGENTS.md`·`CLAUDE.md`에는
  "1인이 수기로 큐레이션한다"는 배경이 있지만, 이건 저장소 내부 문서일 뿐 **사이트
  방문자나 크롤러는 절대 볼 수 없다.**
- 방법론 공개(예: "몇 시에 방문해서 확인하는지", "콘센트를 어떻게 셌는지")가 있다면
  전문성 신호가 크게 올라간다. 지금은 raw 데이터만 있고 그걸 만든 과정이 안 보인다.

### Authoritativeness (권위) — 25% 가중치, 추정 10/100

- 신규 1인 MVP이므로 외부 피인용·backlink·언론 노출이 없는 건 이 단계에서 당연하다
  (결함이라기보다 "아직 획득하지 못한 상태"로 보는 게 맞다).
- 다만 지금 상태에서 권위를 쌓을 구조 자체가 없다 — 개별 카페 페이지가 없으니 특정
  카페에 대해 외부에서 링크를 걸거나 인용할 대상(citable unit)이 없다. 권위를 쌓을
  "표면적"이 아예 없는 셈이다.

### Trustworthiness (신뢰) — 30% 가중치, 추정 45/100 (넷 중 가장 높음)

- **`last_verified`를 UI에 그대로 노출하는 건 진짜 강점이다.** QRG가 강조하는 신선도
  투명성을 정확히 구현했다. 대부분의 로컬 디렉터리 사이트가 숨기는 걸 카공맵은 명시한다.
- 단, 지금 값은 **9곳 전부가 동일한 날짜(임시로 채운 오늘 날짜)** 라고 CLAUDE.md에
  명시돼 있다. noindex가 풀린 뒤 실제 방문 검증 날짜로 갱신되지 않은 채 배포되면,
  "확인일"이라는 신뢰 신호가 오히려 **가짜 신선도(fake freshness)** 로 읽힐 위험이
  있다 — 9곳이 정확히 같은 날 한꺼번에 "확인"됐다는 건 부자연스러운 패턴이고, 이를
  알아챈 사용자나 향후 감사자에게는 역효과다.
- 연락처/문의/운영자 정보/개인정보처리방침/이용약관 페이지가 전무하다. 카카오 로그인,
  리뷰, 제보 같은 개인정보·UGC를 받는 서비스인데 정책 문서가 없다. 개인 습작이라
  법적 강제는 없지만, 신뢰 신호로는 마이너스다.
- HTTPS(Vercel 기본 제공), 명확한 title/description/OG 메타데이터는 잘 돼 있다 — 이건
  좋은 신호다.
- robots meta의 `noindex, nofollow`는 사진 저작권 미확인이라는 **정당한 이유가 문서화된**
  의도적 선택이다. 이 자체는 감점 요인이 아니라 "아직 공개 판정 대상이 아님"으로 봐야
  한다.

## 4. AI Citation Readiness — 15/100

Sept 2025 QRG와 AI 검색(Perplexity, ChatGPT search, Google AI Overview) 관점에서 봐야
할 세 가지가 전부 취약하다.

1. **Quotable facts 없음** — "나루터는 콘센트가 많고 자정까지 영업합니다" 같은 완결된
   서술 문장이 하나도 없다. label:value 조각은 AI가 그대로 인용하기엔 문맥이 없다.
2. **Structured data 0개** — `LocalBusiness`/`Place` JSON-LD가 전혀 없다. 카공맵 데이터
   모델(이름·주소·좌표·영업시간·`amenityFeature` 격인 콘센트/와이파이/소음)은 사실
   `LocalBusiness` + `openingHoursSpecification` + `amenityFeature` 스키마에 거의
   1:1로 매핑되는 이상적인 케이스인데 전혀 활용되지 않고 있다.
3. **URL 단위 인용 불가** — AI 검색 엔진은 대개 "이 문장은 이 URL에서 나왔다"는 형태로
   인용한다. 카페별 고유 URL이 없으므로 "나루터"를 인용하고 싶어도 가리킬 링크가
   `/` 하나뿐이라 인용 단위(citable unit)가 존재하지 않는다.

## 5. 개선 권고 (심각도순)

### Critical — noindex 해제 전에 반드시 필요

1. **카페별 서술 콘텐츠 최소 2~3문장 추가.** "왜 work_fit이 good인지", "어떤 자리가
   좋은지", "언제 가면 붐비지 않는지" 등 1인칭 경험 서술. Experience/Expertise 점수에
   가장 직접적으로 기여한다.
2. **개별 카페에 고유 URL 부여**(`/cafe/[slug]` 또는 `/?cafe=slug` + 서버 렌더 마크업).
   지금처럼 클릭 후에만 나타나는 구조로는 크롤러가 카페 단위로 아무것도 색인할 수 없다.
   RSC flight payload 안의 JSON을 서버 컴포넌트에서 실제 마크업으로도 뿌려주는 형태가
   필요하다(hydration 전 fallback으로).
3. **`LocalBusiness` JSON-LD 추가.** 이미 있는 구조화 데이터(주소·좌표·영업시간·
   콘센트/와이파이/소음)를 그대로 스키마에 옮기면 된다. noindex 상태에서도 미리
   구현해 둘 수 있다 — 색인 여부와 무관하게 지금 붙여도 무해하다.
4. **소개(About) 페이지 신설.** 운영자가 누구고, 왜 이걸 만들었고, 어떤 기준으로
   카페를 판정하는지(방법론) 밝힌다. Expertise·Trustworthiness 둘 다에 걸린다.

### High

5. **`last_verified`를 실제 방문 검증 날짜로 갱신하는 운영 루틴 확립.** 9곳이 전부
   동일 날짜인 현재 상태로 공개하면 신뢰 신호가 오히려 의심을 살 수 있다.
6. **연락처/문의 지면 추가.** 최소한 이메일 하나라도 — UGC(리뷰·제보)를 받는 서비스라
   더 필요하다.

### Medium

7. **사진 출처 명시.** 직접 촬영본으로 교체한 뒤(이미 mvp-decisions.md에 계획됨),
   "직접 촬영" 같은 캡션을 붙이면 Experience 신호로 전환된다.
8. **태그(chips)를 문장 속 자연스러운 키워드로도 재활용.** 지금은 나열형뿐이라 자연스러운
   키워드 사용(natural keyword usage) 평가에서 근거가 부족하다.

### Low (구조적 트레이드오프, 지금 단계에서는 정당함)

9. Authoritativeness는 외부 피인용이 쌓여야 자연히 오르는 항목이라 지금 단계에서
   억지로 끌어올릴 방법은 없다. 위 1~4번이 자리 잡은 뒤 자연 성장을 기대하는 게 맞다.
10. 9곳이라는 카페 수 자체는 "얕음"의 문제가 아니다 — 문제는 각 카페의 콘텐츠 밀도이지
    카페 개수가 아니다. 개수를 늘리기보다 서술 콘텐츠 밀도를 먼저 높이는 게 우선순위다.

## 부록 — 확인 방법

- `claude-seo run render_page.py https://cagongmap-nu.vercel.app/ --mode always --output rendered.html`
  로 Playwright 완전 렌더링 HTML 확보 (`render_ms` ≈ 7000ms, `render_engine`:
  playwright-chromium).
- `extracted_text`(trafilatura) 결과: 58자, 마커 클릭 전 상태와 동일한 수준의 텍스트만 추출됨.
- `structured_data.block_count`: 0.
- `<head>`는 title/description/OG/Twitter Card/canonical/favicon 모두 정상 세팅되어
  있음 — 메타데이터 레이어는 잘 만들어져 있다. 문제는 본문(body) 콘텐츠 레이어다.
- 소스: `components/cafe/CafeCard.tsx`,
  `components/review/ReviewSection.tsx`, `app/layout.tsx`, `data/cafes.json`.
