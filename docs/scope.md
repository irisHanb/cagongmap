# 카공맵 MVP 범위 정리

> 노트북 작업하기 좋은 카페를 지도에서 찾는 서비스
> 최종 갱신: 2026-08-12

관련 문서: [implementation-plan.md](./implementation-plan.md) · [mvp-decisions.md](./mvp-decisions.md) · [research-verification.md](./research-verification.md)

## 합의된 전제

리서치 보고서를 바탕으로 한 논의에서 확정된 방향:

| 항목 | 결정 |
|---|---|
| **1차 목표** | 가설 검증용 MVP (얇게, 빠르게) |
| **데이터 수급** | 운영자 직접 시드 (크롤링 금지 — `mvp-decisions.md` 2-1) |
| **플랫폼** | 웹 (모바일 웹 우선) / Next.js App Router, 포트 3030 |
| **지도 SDK** | **카카오맵 JavaScript SDK** (확정) |
| **대상 권역** | **송파·잠실** (확정) |
| **타겟 세그먼트** | 특정 안 함 (전체) — 단, 필터는 공통 1순위만 |
| **UGC(로그인·제보)** | **최종 목표에 포함. 단, 단계적 도입** — 1차는 조회 전용 |

핵심 전략: UGC에만 의존하지 않고 **작업 적합성 핵심 데이터를 운영자가 시드로 구축**한 뒤, **단일 권역**부터 시작한다.

## ✅ 이번 구현에서 먼저 다룰 기능

1. **지도 기반 카페 탐색** — 모바일 웹, 지도 위에 시드 카페 핀 표시. **송파·잠실** 권역으로 한정.
2. **핵심 필터** — 현재 시드 스키마 기준으로 확정 (아래 스키마 절 참고).
   - 콘센트(`outlet`) · 와이파이(`wifi`) · 소음(`noise`) · 지금 영업중 · 가격대(`iced_americano_price`)
   - ⚠️ 당초 3대 핵심 필터 중 하나였던 **카공 허용은 보류**되었다. 아래 "보류된 차별점" 참고.
3. **카페 상세 카드** — 핀 클릭 시 핵심 속성 + 영업시간 + 네이버 플레이스 링크 + "최근 확인됨"(`last_verified`) 표시.
   - 사진은 직접 호스팅한다 — 마커에 대표 사진, 상세에 좌우 슬라이드 (`mvp-decisions.md` 3절).
     ⚠️ 현재 이미지는 연습용 임시본이라 공개 전 교체가 필요하다.
4. **필터링 / 정렬** — 속성으로 핀을 거르고, 리스트 뷰로도 열람.
5. **운영자 시드 데이터 입력 구조** — 정적 `data/cafes.json` 직접 편집. 관리 화면은 만들지 않는다.

### 구현 순서

1차 구현은 **1번(지도 + 마커 + 상세 카드)까지**만 다룬다. 필터·리스트 뷰는 2차.
상세 단계는 [implementation-plan.md](./implementation-plan.md) 5절 참고.

## ⏸️ 지금은 미뤄도 되는 기능

- **실시간 혼잡도 / 좌석 정보** — 데이터 소스 없음, 구현 난이도 높음. 가설 검증 단계에선 과함.
- **UGC(사용자 제보 / 등록) + 회원가입 / 로그인** — **최종 목표에는 포함**하되 1차 구현에서는 제외.
  - 코드 구조는 미리 열어둔다: 모든 데이터 접근을 `lib/cafes.ts` 한 곳으로 모아, 나중에 정적 JSON → API/DB로 이 파일만 교체하면 되도록 설계한다.
  - 즐겨찾기는 그때까지 로컬스토리지로 대체 가능.
- **제보 인센티브(포인트·뱃지), 신고 / 검증 기능**
- **수익화(광고·송객 제휴)** — 트래픽 임계량 도달 후. 단 업주 이해충돌 이슈가 있음 (`research-verification.md` 2절).
- **권역 확장, 네이티브 앱, 푸시 알림**
- **마커 클러스터링** — 현재 시드 9곳 규모에선 불필요.

## 📍 필요한 장소 데이터 (카페당 시드 스키마)

**현재 `data/cafes.json`의 실제 필드를 기준으로 확정한다.** (별도 스키마를 새로 설계하지 않는다)

| 필드 | 타입 | 비고 |
|---|---|---|
| `id` | string | **추가 예정** — 마커/리스트/상세 연결 키. 이름은 바뀌므로 키로 쓰지 않는다 |
| `name` / `address` / `lat` / `lng` | 필수 | 지도 핀 |
| `outlet` | enum (`many`/`some`/`few`/`none`) | 핵심 필터 1 — 현재 시드엔 `many`/`some`만 등장 |
| `wifi` | boolean | 핵심 필터 2 — 3단계가 아닌 유무만 |
| `noise` | enum (`quiet`/`normal`/`noisy`) | 핵심 필터 3 |
| `work_fit` | enum (`good`/`ok`/`bad`) | 종합 작업 적합도 |
| `open_time` / `close_time` / `is_24h` | string / boolean | 심야·24h 및 "지금 영업중" 판정 |
| `iced_americano_price` | number | 가격대 필터 |
| `naver_place_url` | string | 메뉴·리뷰 등 나머지 상세는 여기로 위임 |
| `tags` | string[] | 자유 태그 |
| `last_verified` | date | **추가 예정** — 신선도 표시 (`mvp-decisions.md` 2-3) |

→ 좌표·주소·영업시간은 공개 정보로 보강 가능하지만, **`outlet`·`noise`·`work_fit`은 운영자가 직접 채워야 하는 핵심 자산**이다.

### ⚠️ 보류된 차별점 — `work_policy` (카공 허용)

이전 버전의 이 문서는 **카공 허용(환영/허용/눈치/금지)**을 "3대 핵심 필터 중 가장 차별적"인 항목으로 규정했다.
현재 시드 스키마에 이 필드가 없어, **이번 범위에서는 도입하지 않기로 결정**했다.

- `work_fit`은 대용이 되지 않는다. **"작업 환경이 좋은가"(환경 품질)와 "눈치 안 보고 있어도 되는가"(매장 정책)는 다른 정보**다.
- 즉 이 서비스는 현재 **당초 정의한 차별점 하나를 의도적으로 비워둔 상태**다.
- 1차 구현(지도+마커)에는 영향이 없다. **필터를 붙이는 2차 이전에 되살릴지 결정해야 한다.** → 미확정 이슈 ②

## ⚠️ 사용자(운영자)가 직접 확인해야 할 가정

1. ~~**권역 선택**~~ → **해결됨.** 송파·잠실로 확정 (기존 시드 9곳 중 7곳이 해당).
   - 권역 밖 2곳(스타벅스 삼성교점, 테라로사 포스코센터점 — 강남구)은 삭제하지 않고 유지한다. 초기 지도 중심을 송리단길로 두면 화면에 안 잡힐 뿐이다.
2. **시드 데이터 수집 방법의 현실성** — **미해결. 여전히 MVP 최대 병목.**
   - 현재 9곳. 목표 규모(50~100곳)까지 어떻게 채울지 미정.
   - 크롤링은 약관 위반으로 배제됨 (`mvp-decisions.md` 2-1) → 직접 방문 또는 리뷰 수기 조사만 남는다.
3. **작업 적합도 판정 기준** — **미해결.** 현재 시드의 `work_fit` / `noise` 값을 직접 방문으로 매겼는지, 리뷰를 보고 추정했는지가 문서화되어 있지 않다. 이 라벨의 신뢰도가 서비스 신뢰도를 좌우한다.
4. ~~**지도 SDK 선택**~~ → **해결됨.** 카카오맵 JS SDK. 무료 쿼터는 계정의 첫 활성화 앱 1개 한정 (`mvp-decisions.md` 2-2).
5. **카카오 콘솔 플랫폼 도메인 등록** — `http://localhost:3030` 등록 필요. 포트가 3030이므로 기본값 3000으로 등록했다면 지도가 뜨지 않는다.

## ❓ 미확정 이슈

① ~~**필터 범위**~~ → **해결됨.** 현재 `cafes.json` 필드 기준(콘센트·와이파이·소음·영업중·가격)으로 구성한다.

② **`work_policy`(카공 허용) 도입 여부** — 2차(필터 구현) 이전에 결정.
   - 도입 시: 필드 추가 + 기존 9곳의 값을 무슨 근거로 매길지 기준 필요.
   - 미도입 시: `scope.md`가 정의한 핵심 차별점 없이 진행하게 된다.

③ **검증하려는 핵심 가설** — MVP 성패 지표를 정하는 기준. **여전히 미확정.**
   - 현재 제안(기본값): **"기존 방법(지도+블로그 교차검색)이 불편해서, 작업 특화 속성으로 필터링되는 전용 지도가 있으면 쓴다."**
   - 대안: "혼잡도 / 실시간성"이 진짜 핵심 가설일 수도 있음 → 이 경우 미뤄둔 실시간 기능을 앞당겨야 함.
   - 참고: 동일 컨셉의 선행 서비스가 국내에 이미 존재했고 성장하지 못했다 (`research-verification.md` 0절).

## 변경 이력

**2026-08-12** — 구현 착수 논의를 반영해 갱신
- 권역을 **송파·잠실**로 확정 (기존: 강남/홍대/성수 중 미정)

- **`work_policy`(카공 허용) 보류** 및 그 대가를 명시 — 미확정 이슈 ②로 승격
- 미확정 이슈 ①(필터 범위) 해결 처리
